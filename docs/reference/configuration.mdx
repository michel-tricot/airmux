airmux runtime commands read YAML from `--config`, then `AIRMUX_CONFIG`. Gateway commands use
`./.airmux/airmux.yml`, falling back to a shared `./airmux.yml` when the standalone file is absent. Control-plane
commands use `./airmux.yml`. The all-in-one image uses `deploy/docker/airmux.yml`.

## Docker Compose variables

| Variable                  | Default                 | Purpose                                      |
| ------------------------- | ----------------------- | -------------------------------------------- |
| `AIRMUX_PORT`             | `8080`                  | Published host port                          |
| `AIRMUX_PUBLIC_URL`       | `http://localhost:8080` | Compose value mapped to the console origin   |
| `AIRMUX_PUBLIC_SIGNUP`    | `false`                 | Allow account creation after instance claim  |
| `POSTGRES_PASSWORD`       | `airmux`                | Initial local Postgres password              |
| `AIRMUX_IMAGE`            | `airmux:local`          | Image used by every role in either topology  |

Hosted deployments set `DATABASE_URL` directly. `DIRECT_DATABASE_URL`, when present, is used by the `setup` role for
migrations while the control plane keeps the pooled URL.

## YAML structure

```yaml
vars:
  cache_dir: .airmux

control_plane:
  database:
    url: ${env:DATABASE_URL:-postgresql+asyncpg://airmux:airmux@127.0.0.1:5432/airmux}
  bootstrap:
    token: ${file:${var:cache_dir}/dataplane.key}
  console_url: ${env:AIRMUX_CONSOLE_URL:-http://127.0.0.1:5000}
  public_signup: ${env:AIRMUX_PUBLIC_SIGNUP:-false}
  secrets:
    kind: file
    root: ${var:cache_dir}/secrets

data_plane:
  bundle:
    kind: remote
    control_plane: &control_plane_link
      url: ${env:AIRMUX_DATAPLANE_CONTROL_PLANE_URL:-http://127.0.0.1:8000}
      token: ${file:${var:cache_dir}/dataplane.key}
    cache_dir: ${var:cache_dir}
    poll_interval_s: 5
    heartbeat_interval_s: 30
  events:
    kind: sqlite
    control_plane: *control_plane_link
    cache_dir: ${var:cache_dir}
    flush_interval_s: 5
  secrets:
    kind: file
    root: ${var:cache_dir}/secrets
```

Both planes must configure the same secret store. A remote data plane uses a management key with bundle-read, usage-ingest, and heartbeat permissions.

## References and variables

| Syntax                   | Behavior                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `${env:NAME}`            | Environment value; a missing reference resolves the enclosing scalar to null and required-field validation fails |
| `${env:NAME:-fallback}`  | Environment value with a fallback                                                                                |
| `${file:path}`           | Trimmed file contents                                                                                            |
| `${file:path:-fallback}` | File contents with a fallback when absent                                                                        |
| `${var:name}`            | Text substitution from the top-level `vars` mapping                                                              |

Refs can appear inside a larger string. Variables resolve before environment and file refs. Relative file references and runtime
paths resolve against the containing configuration file; a local bundle resolves its taxonomy and key references against the bundle file.

## Bundle sources

| Kind     | Fields                                                                  |
| -------- | ----------------------------------------------------------------------- |
| `remote` | `control_plane`, `cache_dir`, `poll_interval_s`, `heartbeat_interval_s` |
| `local`  | `path`, `reload_interval_s`                                             |

Remote defaults are 30 seconds for poll and heartbeat intervals. Local bundle reload defaults to 2 seconds.

## Event outboxes

| Kind      | Use                                                                            |
| --------- | ------------------------------------------------------------------------------ |
| `sqlite`  | Durable queued usage export; requires a control-plane link and cache directory |
| `file`    | Append-only local JSON Lines usage collection; requires `path`                 |
| `devnull` | Discard usage; standalone development only                                     |

SQLite flush defaults to 5 seconds. Workers sharing one gateway cache directory coordinate through the same outbox.

The file sink resolves `path` relative to the configuration file, creates missing parent directories, and creates new
files with mode `0600`. It appends one complete usage event per line and flushes each event before `record` returns.
Threads and processes sharing a local file serialize their writes. Restarting appends to the existing file.
It has no export queue, deduplication, rotation, or `fsync` guarantee; health reports zero pending events.
Use it on a local POSIX filesystem. File write failures propagate to the request instead of silently discarding usage.

## Secret stores

| Kind                | Use                                                                    |
| ------------------- | ---------------------------------------------------------------------- |
| `file`              | One private file per credential; default managed deployment            |
| `env`               | One effective credential per provider; standalone or single-tenant use |
| `insecure_database` | Postgres-backed prototype store                                        |
| `memory`            | Tests and ephemeral development                                        |

The environment store checks `AIRMUX_SECRET_PROVIDER_<PROVIDER>` before `<PROVIDER>_API_KEY`. Scope and credential name
are not part of its lookup, so it cannot isolate tenant-specific values.
