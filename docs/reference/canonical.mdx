---
title: "Canonical API"
description: "Reference TokKeeper's provider-neutral request, response, content parts, and streaming chunk schema."
---

Send canonical JSON to `POST /inf/v1/chat/completions`. Raw requests that no other ingress adapter claims use canonical
automatically.

## Request

```json
{
  "model": "openai/gpt-4o-mini",
  "messages": [
    {"role": "system", "content": "Be concise."},
    {"role": "user", "content": "Say hello"}
  ],
  "stream": false,
  "max_tokens": 128
}
```

Message `content` may be a string shorthand for one text part. The stored and emitted form is always a typed array.

## Request fields

| Field | Type | Constraint |
| --- | --- | --- |
| `model` | string | Required |
| `messages` | array | At least one message |
| `stream` | boolean | Strict boolean; default `false` |
| `max_tokens` | integer or null | At least 1 |
| `temperature` | number or null | At least 0 |
| `top_p` | number or null | Greater than 0 and at most 1 |
| `stop` | string array or null | Provider stop sequences |
| `seed` | integer or null | Forwarded when supported |
| `tools` | tool array or null | Function definitions |
| `tool_choice` | string, named tool, or null | `auto`, `none`, `required`, or `{name}` |
| `response_format` | object or null | `text`, `json_object`, or `json_schema` |
| `reasoning` | object or null | Type, effort, summary, budget, or display |
| `parallel_tool_calls` | boolean or null | Strict boolean |

The request top level accepts provider-specific extras. Nested message, content, tool, reasoning, and response-format objects are closed.

## Content parts

<Tabs>
  <Tab title="Text">
    ```json
    {"type": "text", "text": "Hello", "cache": "ephemeral"}
    ```
  </Tab>
  <Tab title="Image URL">
    ```json
    {"type": "image", "url": "https://example.com/image.png"}
    ```
  </Tab>
  <Tab title="Inline image">
    ```json
    {"type": "image", "data": "iVBORw0KGgo...", "media_type": "image/png"}
    ```
  </Tab>
  <Tab title="Document">
    ```json
    {"type": "document", "data": "JVBERi0...", "media_type": "application/pdf", "filename": "report.pdf"}
    ```
  </Tab>
  <Tab title="Tool call">
    ```json
    {"type": "tool_call", "id": "call_1", "name": "get_weather", "arguments": "{\"city\":\"Paris\"}"}
    ```
  </Tab>
  <Tab title="Tool result">
    ```json
    {"type": "tool_result", "call_id": "call_1", "content": "18 C", "is_error": false}
    ```
  </Tab>
</Tabs>

An image needs exactly one of `url` or `data`; inline data also requires `media_type`. A document needs exactly one of
`url`, `data`, or `file_id`; inline data requires `media_type`.

## Response

```json
{
  "id": "019...",
  "model": "openai/gpt-4o-mini",
  "content": [{"type": "text", "text": "Hello!"}],
  "finish_reason": "stop",
  "usage": {
    "input_tokens": 8,
    "output_tokens": 2,
    "cache_read_tokens": 0,
    "cache_write_tokens": 0,
    "estimated": false
  },
  "gateway": {"finish_reason": "stop", "adjustments": []}
}
```

## Stream chunks

Incremental chunks carry one `delta` of type `text`, `reasoning`, or `tool_call`. The closing chunk carries
`finish_reason`, `usage`, and `gateway` with no `delta`, followed by `[DONE]`.

The generated JSON Schemas are committed at `taxonomy/schemas/completion/tokkeeper.request.yaml`, `tokkeeper.response.yaml`, and `tokkeeper.stream.yaml`.
