title: "Usage and activity"
description: "Inspect model usage, cost, latency, request status, gateway health, and audited management changes."
---

airmux records one usage event for each upstream attempt, including failed and cancelled attempts. Gateways accept events
without waiting for local persistence. SQLite deployments export durable events to the control plane in batches.

## Usage event fields

| Field | Meaning |
| --- | --- |
| `request_id` | One caller request; fallback attempts share this ID |
| `event_id` | Unique event ID for one attempt |
| `model_id`, `provider_id` | Route used for the attempt |
| `input_tokens`, `output_tokens` | Provider-reported or estimated counts |
| `cache_read_tokens`, `cache_write_tokens` | Cache traffic included in input tokens |
| `cost_usd` | Cost derived from catalog rates and token counts |
| `latency_ms` | Attempt latency observed by the gateway |
| `status` | `ok`, a denial or provider failure class, or `cancelled` |
| `credential_id`, `credential_scope` | Credential metadata without the secret value |
| `bundle_id` | Configuration version that governed the request |

Costs use the prices stored in the catalog at request time. When complete provider usage is unavailable, airmux marks the event's usage as estimated.

## Inspect usage

```bash
airmux events list
airmux events tail --interval 2 --keep 30
```

The console shows workspace usage and instance or organization activity where the current principal has permission. The
management API supports opaque cursor pagination.

The workspace overview counts **attempt events**. One caller request has one `request_id`, and credential or model
fallback can produce several attempt events with that ID. Failed, cancelled, and denied events count too, including
denials before an upstream call.

Attempt counts, input and output tokens, spend, and the top five models all use the same window: up to the latest 200
events recorded for the workspace, ordered by descending event ID. Recent Activity shows the first eight events from
that window. Per-model attempt counts use the model recorded on each event. These are event-window totals, with no
fixed time interval; a request's other attempts can fall outside the window or arrive later. The overview refreshes
every three seconds and does not load older pages to calculate its metrics.

The instance overview's organization total counts every organization currently stored on the instance, including
personal organizations. Deleted organizations no longer count. The total comes from
`GET /api/v1/instance/organizations/summary`, independently of collection pagination or previously loaded console pages.
It requires instance-scoped `organizations.read` permission and returns `{"data":{"total":51}}` for an instance with
51 organizations.

## Gateway health

```bash
airmux gateways list
curl http://localhost:8080/healthz
curl http://localhost:8080/readyz
```

`/healthz` is dependency-free process liveness. `/readyz` returns `503` when the gateway has no accepted bundle. Inspect
`/metrics` on the data plane's internal listener for queue depth, durable backlog age, export failures, and rejected
bundle manifests. A gateway is reported offline after 90 seconds without a heartbeat. See
[production operations](/docs/deployment/operations#opentelemetry-metrics) for the metric reference and export guidance.

## Audit activity

Control-plane writes to audited resources are attributed to the acting user by database triggers. Activity views expose
the before and after state while excluding database-owned timestamps. Usage events and audit activity answer different
questions: usage describes inference attempts; audit activity describes management changes.
