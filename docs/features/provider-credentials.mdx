---
title: "Provider credentials"
description: "Store upstream API keys at instance, organization, or workspace scope and control which requests may use them."
---

Provider credentials are upstream API keys that `airmux` uses after an inference request has been authenticated and
routed. They are separate from inference keys and management keys.

## Credential scopes

| Scope | Available to |
| --- | --- |
| Instance | Every organization unless policy excludes `platform` credentials |
| Organization | Every workspace in one organization |
| Workspace | One workspace |

## Add a credential

The webapp exposes credentials at instance, organization, and workspace settings. The CLI creates organization or workspace credentials:

```bash
printf '%s' "$OPENAI_API_KEY" | airmux provider-credentials add openai --name production --priority 10
```

Add `--org` to share the credential across the active organization. Without it, the credential belongs to the selected workspace.

```bash
airmux provider-credentials list
airmux provider-credentials list --org
```

Values are never returned. Lists show metadata, the last four characters, current version, enabled state, and observed health.

## AWS Bedrock and Azure OpenAI

For AWS Bedrock, create a Bedrock API key and store it as a provider credential for `bedrock`. Use the regional
OpenAI compatible endpoint, such as `https://bedrock-mantle.us-east-1.api.aws/v1`, and set the model's upstream name to
the Bedrock model ID. Bedrock API keys are bearer tokens. The OpenAI compatible endpoint supports only the models and
features AWS exposes through that API; AWS IAM access key pairs are not accepted by this adapter.

For Azure OpenAI, store the resource key as a credential for `azure_openai`. Set the provider base URL to the
resource's versioned endpoint, for example `https://RESOURCE.openai.azure.com/openai/v1`, and set the model's upstream
name to its deployment name. The adapter sends the key in `api-key` and uses the Azure OpenAI v1 API. Configure each
deployment as a model entry. Image inputs, tools, reasoning, and structured output depend on the deployed model and
are limited to the capabilities declared for that model in the catalog.

## Rotate, disable, or delete

```bash
printf '%s' "$OPENAI_API_KEY_NEXT" | airmux provider-credentials rotate "$CREDENTIAL_ID"
airmux provider-credentials disable "$CREDENTIAL_ID"
airmux provider-credentials disable "$CREDENTIAL_ID" --enable
airmux provider-credentials rm "$CREDENTIAL_ID"
```

## Selection and health

Within the selected scope, lower priority values are tried first. Credential status is advisory and reflects the latest
ingested request event: `unknown`, `live`, `invalid`, or `rate_limited`. Request-time selection also uses an in-memory
cooldown after a rate limit.

Use a `credential_access` rule to allow only selected scopes. 

## Secret stores

The default managed deployment uses a file-backed store.

Standalone mode uses environment variables and can resolve only one value per provider, making it appropriate for local or single-tenant use. 

Both planes must point at the same store when deployed separately.
