The Messages API is available at `/inf/v1/messages`. The client base URL ends at `/inf`; the SDK appends `/v1/messages`.

```bash
export AIRMUX_URL='http://localhost:8080'
export AIRMUX_INFERENCE_KEY='sk-inf-your-key'
export AIRMUX_MODEL='anthropic/claude-sonnet-4-6'
```

```python
import os

from anthropic import Anthropic

client = Anthropic(
    base_url=f"{os.environ['AIRMUX_URL'].rstrip('/')}/inf",
    api_key=os.environ["AIRMUX_INFERENCE_KEY"],
)

message = client.messages.create(
    model=os.environ["AIRMUX_MODEL"],
    max_tokens=256,
    messages=[{"role": "user", "content": "Explain request routing in one sentence."}],
)

print(message.content[0].text)
```

The SDK sends the airmux inference key in `x-api-key`. Provider credentials are resolved separately by the gateway.

## Route to another provider family

The request dialect and provider route are independent. Keep the Messages request shape and set `model` to any
compatible catalog model, such as `openai/gpt-4o-mini`. airmux translates the request and renders the response back in
Messages format.

Capability checks happen before the provider call. A request with tools, reasoning, structured output, images, or PDFs
is rejected when the selected model does not advertise the required capability or input modality.

## Stream a response

```python
with client.messages.stream(
    model=os.environ["AIRMUX_MODEL"],
    max_tokens=256,
    messages=[{"role": "user", "content": "Count from one to five."}],
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
```

The response uses named Messages SSE events even when the upstream provider uses another stream format.

## Run the repository example

```bash
uv run --with anthropic python examples/anthropic_sdk.py
```
