---
title: "Generate structured output"
description: "Request a JSON object or strict JSON Schema output and understand capability enforcement."
---

Structured output is available when the selected catalog model advertises `structured_output`. AirLLM rejects an
unsupported route before contacting the provider.

## Canonical request

```bash
curl http://localhost:8080/inf/v1/chat/completions \
  -H "Authorization: Bearer $AIRLLM_INFERENCE_KEY" \
  -H 'Content-Type: application/json' \
  -H 'x-airllm-dialect: canonical' \
  -d '{
    "model": "openai/gpt-4o-mini",
    "messages": [{"role": "user", "content": "Return the population of Paris"}],
    "response_format": {
      "type": "json_schema",
      "json_schema": {
        "name": "city_population",
        "strict": true,
        "schema": {
          "type": "object",
          "properties": {
            "city": {"type": "string"},
            "population": {"type": "integer"}
          },
          "required": ["city", "population"],
          "additionalProperties": false
        }
      }
    }
  }'
```

The response content is still text. Parse the returned text as JSON in your application and validate it against the same schema.

## Dialect mappings

| Surface | Field |
| --- | --- |
| Canonical | `response_format: {type: "json_schema", json_schema: {...}}` |
| Chat Completions | `response_format: {type: "json_schema", json_schema: {...}}` |
| Responses | `text.format: {type: "json_schema", ...}` |
| Messages | `output_config.format: {type: "json_schema", schema: {...}}` |

Use `type: "json_object"` when you only require valid JSON and do not need a schema. A plain `text` response does not
require the structured-output capability.

<Tip>
  Add a [strict parameter policy](/docs/policies#require-parameter-support) when every explicitly supplied optional
  parameter must reach the provider unchanged.
</Tip>
