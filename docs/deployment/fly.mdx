---
title: "Fly.io"
description: "Deploy one TokKeeper Machine with a persistent volume and Managed Postgres."
---

The checked-in `deploy/fly/fly.toml` runs the all-in-one image on one Machine. Keep the application, volume, and database in the same region.

## Provision

Install and authenticate `flyctl`, choose an app name, and change `primary_region` in `deploy/fly/fly.toml` if you do not want `sjc`.

```bash
flyctl launch --config deploy/fly/fly.toml --name my-tokkeeper --no-deploy --no-db
flyctl mpg create --name my-tokkeeper --region sjc
```

Attach the cluster ID returned by the second command:

```bash
flyctl mpg attach CLUSTER_ID --app my-tokkeeper --config deploy/fly/fly.toml
```

The attachment sets the pooled `DATABASE_URL`. Copy the direct connection URL from the database dashboard and stage it for migrations:

```bash
flyctl secrets set --app my-tokkeeper --stage \
  DIRECT_DATABASE_URL='postgresql://USER:PASSWORD@direct.CLUSTER.flympg.net/DATABASE'
```

Keep Managed Postgres in session pooling mode. Startup uses the direct URL for migrations and the pooled URL for application traffic.

## Deploy and claim

```bash
flyctl deploy --config deploy/fly/fly.toml --app my-tokkeeper --ha=false \
  --env TOKKEEPER_CONSOLE_URL=https://my-tokkeeper.fly.dev

uv run --package tokkeeper --no-dev --frozen tokkeeper quickstart \
  --url https://my-tokkeeper.fly.dev
```

Keep `--ha=false`: this layout owns one `/state` volume and runs one gateway. Use [separate services](/docs/deployment/scaling) to design replicas.

## Update

Repeat the deploy command with the same app name and origin after taking database and volume backups. Moving regions
requires migrating both the volume and database.

For GitHub Actions, set `FLY_API_TOKEN` as a secret and `FLY_APP` as a variable in the `production` environment, then
run the checked-in `deploy-fly` workflow.
