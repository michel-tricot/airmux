[Deploy to Render](https://render.com/deploy?repo=https://github.com/michel-tricot/tokkeeper)

The `render.yaml` Blueprint creates:

- One Docker web service using the all-in-one image
- A persistent disk mounted at `/state`
- Postgres 16 with an internal connection URL

The selected plans use paid compute and storage. Review the price shown before creation.

## Deploy

Use the deploy link, or choose **New > Blueprint** and connect your fork. The Blueprint sets `DATABASE_URL` from the
managed database and defaults the public origin to `RENDER_EXTERNAL_URL`.

As soon as the service becomes reachable, claim it:

```bash
uv run --package tokkeeper --no-dev --frozen tokkeeper quickstart \
  --url https://your-service.onrender.com
```

Provider keys remain on the machine running `quickstart` until the CLI stores them through the management API.

## Custom domain and updates

For a custom domain, set `TOKKEEPER_CONSOLE_URL` to its exact HTTPS origin and redeploy. Trigger updates manually after
backing up the database and persistent disk. Migrations run during startup.

Keep one application instance in this layout because its gateway owns one persistent disk. Use the
[split deployment model](/docs/deployment/scaling) for horizontal gateway scaling.
