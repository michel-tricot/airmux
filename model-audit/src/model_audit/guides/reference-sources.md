# Where the facts live

In preference order. Stop at the first that answers the question; do not average sources.

## 1. The vendor's OpenAPI spec

The only source that gives request and response shape together, with types and enums.
Locations worth trying, roughly in hit order:

```
https://<docs-host>/openapi.json          docs.x.ai, docs.z.ai, docs.perplexity.ai
https://<api-host>/openapi.json           api.ai21.com, api.deepinfra.com, api.reka.ai
https://<docs-host>/openapi.yaml          docs.together.ai
https://<api-host>/v1/openapi.json
https://<vendor-site>/openapi.json        novita.ai, openrouter.ai
raw.githubusercontent.com/<vendor>/<docs-repo>/main/openapi.yaml
```

Mistral's lives in `mistralai/platform-docs-public`. Cohere's in
`cohere-ai/cohere-developer-experience`. OpenAI's in `openai/openai-openapi`.

## 2. The Stainless `.stats.yml` trick

Vendors whose SDK is generated by Stainless publish the spec at a content-addressed URL
named in the SDK repo:

```
https://raw.githubusercontent.com/<vendor>/<sdk-repo>/main/.stats.yml
  -> openapi_spec_url: https://storage.googleapis.com/stainless-sdk-openapi-specs/...
```

Confirmed for OpenAI, Anthropic, Groq and Cerebras. The hash changes on every
regeneration, so record the `.stats.yml` URL in `openapi`, never the hashed URL.

## 3. A model enum inside the spec

Better than any pricing page for model ids, because it is the set the API validates
against. Pricing pages print display names: Z.ai's says `GLM-5.2`, the API wants
`glm-5.2`. Map an authoritative enum in the provider source or add the sourced exception
through `airmux-audit models add`.

Caveat: an enum can be staler than the docs. Groq's spec still lists `compound-beta` while
its models page has moved on. When they disagree, prefer the docs and note the conflict.

## 4. The vendor's documentation

A parameter table is good evidence of what is accepted and no evidence of what is
rejected, so schemas transcribed from one get `additionalProperties: true` and an
`x-notes` array for rules a schema cannot express, such as "accepted then ignored".

Mintlify sites often expose `/llms.txt` listing every page, which beats guessing URLs.
Provider source modules should extract official model pages on every sync when the model
API omits limits, prices, modalities, tiers, or deprecations. Record the exact page in
`documentation_url`, preserve units and pricing tiers, and test the parser against a frozen
representative fragment. Never label a per-minute or per-image rate as a token rate.

## 5. Probing the live API

For things nobody documents:

- **Auth mechanism.** Send a deliberately invalid key and read the error. Anthropic returns
  `invalid x-api-key`, naming the header. If it says "bearer token", the header was parsed
- **Open vs gated catalogs.** An unauthenticated `GET /v1/models`. Five providers answer
- **Whether a surface exists at all.** POST with a bogus body; a 404 and a 400 mean
  different things

## 6. Secondary indexes, for remaining gaps only

Prefer provider-scoped models.dev before OpenRouter. OpenRouter's `/api/v1/models` publishes `context_length` for every model it serves and
`max_completion_tokens` for most, plus `hugging_face_id` and `canonical_slug` so the same
open-weights model matches across vendors. It filled 289 gaps.

Use it for limits. Do not use it for request shape: a router's schema is a superset of
everyone's and says nothing about what one provider accepts.

## Sources that look reliable and are not

- **Hugging Face `config.json`** reports `max_position_embeddings`, the architectural
  limit, not what a provider serves. Yi-1.5-34B reports 4096 there and is served at 32k
- **Search result summaries.** Fine for finding a URL, never for the value itself. Always
  confirm on the vendor's own domain
- **Another provider's catalog entry** for the same model. Serving limits differ per host
